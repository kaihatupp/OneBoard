# OneBoard

予定管理(カレンダー)を起点に、少しずつ機能を足していく個人利用向けアプリ。
プレーンな HTML / CSS / JavaScript のみで作られており、ビルド不要・オフライン完結。
データはブラウザの `localStorage` にのみ保存され、外部サーバーへの送信は一切行わない。

## 使い方

### PC(ローカル)

`OneBoard起動.bat` をダブルクリックすると、ローカルサーバー(`http://localhost:8123/`)が
起動して Chrome が新しいウィンドウで開きます。ウィンドウ/タブを閉じるとサーバーも停止します。
※ Python が必要です。

### スマホ(PWA)

GitHub Pages で公開しています。スマホの Chrome で公開URLを開き、メニューから
「ホーム画面に追加」するとアプリとして使えます(オフライン対応)。
PC版とスマホ版はデータを共有しません(同期は将来フェーズ)。

- 公開URL: https://kaihatupp.github.io/OneBoard/
- リポジトリ: https://github.com/kaihatupp/OneBoard

## フェーズ1でできること

- 月表示カレンダー(祝日・土日の色分け)
- 祝日表示(内閣府「国民の祝日」データを `holidays.json` に同梱)
- 予定の登録・編集・削除(終日 / 時刻、色、メモ)
- 繰り返し予定(毎月◯日 / 毎月第◯曜日・最終◯曜日、終了日の指定、特定日だけ除外)

## フェーズ2a

- PWA 化(ホーム画面に追加・スタンドアロン起動・オフライン表示)
- スマホ画面向けのレスポンシブ対応
- GitHub Pages で公開

## フェーズ2b(進行中)

- 予定の入力は PC、スマホは閲覧専用
- PC で予定を編集すると数秒後に自動で暗号化 → `git push` → スマホが取得して表示
  (「スマホに反映」ボタンでの手動反映も可。自動反映はデータ画面でオフにできます)
- データは端末のパスフレーズで暗号化(Web Crypto)。GitHub 上でも中身は読めない
- **あとで入力メモ(捕捉インボックス)**: スマホで「後で PC で入力」したい用事を 📋 からメモ。
  「PC へ渡す」で暗号化ファイル/コピー → PC の「データ」画面で取り込むと、PC 起動時に一覧が開いて
  「予定にする」で本入力できます。
- **PC 復元**: PC を買い替えたときなど、データ画面の「GitHub から復元」で公開中の配信データを
  直接取り込めます(パスフレーズ必須)。

## フェーズ3a / 3b / 3c(タスク管理)

- ヘッダーの「カレンダー / タスク」タブで画面を切り替え。
- タスクの追加・編集・削除(件名 / 期限日 / 進行中トグル / 本文)。
- 一覧は期限に応じた区分セクションで表示: 進行中 / 期限切れ / 今日 / 明日 / 今週 / 来週 /
  今月 / 来月 / 後で(該当なしの区分は非表示。週の始まりは月曜)。
- 「進行中」のタスクは最上段に赤字で表示。
- **完了チェック**: 各行のチェックで完了。最下部の折りたたみ「完了済み」セクションへ移動(外すと戻る)。
- **携帯同期(3c)**: タスクも予定と同じ暗号化配信に乗るようになり、スマホでも閲覧できます
  (スマホは閲覧専用 = チェック・追加・編集はなし)。PC の「GitHub から復元」もタスクを含みます。
- テンプレート・一括移動・カレンダー連携は今後のフェーズで追加予定。

通知機能は将来フェーズで検討します。

## 開発メモ

### 本番用 bot と 開発用 bot

| bot | いつ使う | Chrome プロファイル |
|---|---|---|
| `OneBoard起動.bat` | 普段の利用(本番) | 既定プロファイル(= 本番データ) |
| `OneBoard開発用起動.bat` | 機能追加中の動作確認 | 専用プロファイル `.dev-profile/`(本番と完全分離) |

開発用 bot は本番の `localStorage`(予定・タスク)に一切触れません。初回は空なので、
DevTools コンソールで次を実行してダミーデータを入れます:

```js
fetch('/dev-seed.js').then(r => r.text()).then(eval)
```

(または [`dev-seed.js`](./dev-seed.js) の中身をコンソールに貼り付け)

設計方針・データモデル・祝日データの更新手順・本番データの取り扱いルールは
[`CLAUDE.md`](./CLAUDE.md) を参照。
